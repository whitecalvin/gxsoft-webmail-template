## 판정과 증거 기준

전체 목표는 미완료다. 파일/함수 존재, 합성 통과, BUILD_ID 존재만으로 운영 데이터·브라우저·권한·영속성·전달 성공을 판정하지 않는다. 아래 구현 관측은 현재 소스를 확인한 결과이며, 과거 실계정 기록은 그 당시 승인된 계정/메일/배포에만 적용한다. 이번 점검에는 운영 API/DB 요청이나 메일 변경을 실행하지 않았다.

원래 목표의 mock 유지와 과거 포트는 후속 사용자 지시로 대체됐다. 현재 `lib/tastemail/server.ts`는 live-only이며 기본 loopback 6711/서버 전용 `TASTEMAIL_API_URL`을 사용한다. 실제 배포 주소와 TLS/터널 가용성은 실행 시 재확인이 필요하다. 폐기된 포트를 현재 진단 기본값으로 재사용하지 않는다. README의 과거 mock/로컬 저장 기록을 현재 실행 지침으로 사용하지 않는다.

## 이번 점검의 직접 검증

현재 입력으로 `test-live-only.mjs`, `test-tastemail-server.mjs`, `test-session-route-boundary.mjs`가 통과했다. 실제 NextResponse 쿠키 정책/Origin·전송 경계/MFA·만료·권한·오류 매핑/불명 로그아웃은 합성 upstream으로 검사했다. 이 세 검사는 네트워크를 사용하지 않았으며 실제 세션·TLS·메일 조회 증거가 아니다.

최근 `.next-gmail-start-validation/BUILD_ID` 21바이트 산출물을 확인했다. 이전 기능 빌드의 성공과 파일 존재는 확인할 수 있지만 다른 세션의 변경까지 포함한 현재 전체 입력 해시 검증 또는 전체 제품 수용으로 주장하지 않는다. 이번 변경은 증거·문서 정리뿐이므로 앱 재컴파일/전체 테스트/언어 검사를 추가 반복하지 않는다.

## 다음 수용 순서와 권한 경계

### 현재 브라우저 접근 증거

현재 사용자 탭에서 설정 경로를 실제 조회할 수 있다. 편지함 표시 선택의 기본/개인 목록, 서버 설정을 받은 활성 컨트롤, 초안 변경 및 취소 복원을 확인했다. 이전 브라우저 접근 제한을 현재 공통 차단 사유로 사용하지 않는다. [구체적 검증 범위](mailbox-visibility-integration-20261011.md). 운영 설정 저장/복원 검증은 별도 승인 대기이며, MFA·세션 만료·권한 거부·장애 유도는 대상 계정과 실행 범위 확인이 필요하다.

### 후속 로컬 실행 관측

2026-10-11 로그인 입력 경계 보완 후, 실제 호스트의 읽기 전용 `netstat -ano -p tcp` 검사에서 7540 LISTENING 항목 1개를 확인했다. 격리 실행 환경에서는 TCP 행이 4개만 보이고 해당 리스너가 보이지 않았지만, 호스트 조회에서는 317개 행과 리스너가 확인됐다. 격리 환경의 조회 결과만으로 서버 종료를 판정하거나 프로세스를 재시작하지 않았다. 이 확인은 TCP 리스너 존재만 입증하며 HTTP 정상 응답·TLS·백엔드 연결·인증 성공은 입증하지 않는다.

현재 `app/[locale]/(workspace)/settings/layout.tsx`는 로그인 세션을 확인한 후 `initialLinkedAccounts()` 결과를 계정별 키를 가진 Provider에 전달한다. 따라서 계정 목록의 서버 초기 조회 경로는 소스상 존재한다. 실제 SSR 응답과 사용자 화면의 데이터 일치는 브라우저/실서버 수용 검증이 남아 있다. 로그인 본문 제한의 별도 검증 기록은 [로그인 입력 경계](login-body-boundary-20261011.md)를 참조한다.

1. 현재 실행 인스턴스·안전한 전송 경로·대상 테스트 계정을 확정한다. 서버 설정/재시작/DB 변경으로 연결성을 임의 복구하지 않는다.
2. 승인된 읽기 전용 검증부터 세션·편지함 요약·두 페이지·상세·검색·첨부를 대조한다. 화면 자동 읽음·원격 이미지 요청은 통제하며 메일 본문/인증정보를 산출물에 기록하지 않는다.
3. 별도 승인된 새 합성 메일에 한정해 변경·초안·자기 발송·첨부 및 실패 경로를 검증한다. 기존 메일/특권 작업/일정 알림/외부 수신자로 범위를 넓히지 않는다.
4. 외부 계정의 실제 인증/worker 및 운영 관리자 변경은 각각 계약·대상·권한을 확정한 뒤 검증한다. 현재 사용자에게 아직 요청하지 않은 예약 중지/작업 영수증 계약을 있다고 가정하지 않는다.
5. 브라우저 접근 제한이 해제되거나 사용자가 제공한 화면/검수 결과로 확인할 수 있는 범위를 진행한다. 정책 제한을 다른 브라우저/원시 요청/디버깅 채널로 우회하지 않는다.

안전한 소스 구현은 계속할 수 있다. 그러나 운영 요청·실계정 변경·브라우저 수용 증거가 없는 상태에서 목표를 완료 처리하지 않는다.

# 연결 계정 메일 보기 UI

후속: 첨부 다운로드 버튼과 소유 계정/메일 metadata의 크기로 제한하는 바이너리 BFF를 연결했다. 아래 첨부 다운로드 미지원 기록의 다운로드 부분보다 최신이다. 인라인 이미지는 여전히 미지원이며 실제 서비스/GUI 수용은 남는다. [다운로드 범위](linked-attachment-download-20261011.md).

## 연결 범위

설정의 연결 계정 목록에서 메일 아이콘을 누르면 공통 Modal이 열린다. 서버가 `read`를 광고한 계정만 선택할 수 있다. 현재 계정 선택값을 바꾸면 revision/인증 세대별 자식 화면을 새로 만들어 이전 계정의 폴더·메일·본문을 제거한다. 기본 계정의 MailProvider/JMAP 목록 상태는 변경하지 않는다.

`폴더 불러오기`는 공통 ConfirmDialog에서 외부 서버 접속과 토큰/연결 상태 갱신 가능성을 고지한 뒤 Provider의 직렬화된 POST를 실행한다. SSR/마운트 시 외부 인증·LIST·동기화를 자동 실행하지 않는다. 폴더 표시명과 실제 IMAP 요청 식별자를 분리한다. 인증 만료 상태에서 폴더를 새로 조회하는 우회는 제공하지 않는다.

폴더를 선택하면 같은 출처 캐시 GET 목록을 읽는다. 다음 페이지는 마지막 UID의 exclusive cursor를 사용하며, 이전 페이지는 cursor stack을 복원한다. 상세 요청은 정확한 연결 계정/폴더/UIDVALIDITY/UID를 보내고 응답의 동일 식별자를 확인한다. 별도 기본 편지함 ID/JMAP Email ID나 날짜·총 개수를 만들지 않는다.

폴더/페이지 변경 시 본문과 선택을 즉시 비운다. 조회 효과는 unmount/의존성 변경에 AbortController를 취소하며 늦은 응답의 상태 갱신을 차단한다. 캐시 GET의 클라이언트 제한 시간은 25초다. 세션/권한/요청 제한/서비스 배포·충돌 오류를 기존 번역으로 표시한다. 실패 시 mock 메일을 만들지 않는다.

## HTML 및 첨부

HTML은 기존 `LiveHtmlMessageBody`의 `isolatedReadOnly` 모드를 사용한다. 기존 CSP와 sandbox/referrer·링크/높이/실패 이미지 정책을 그대로 유지한다. 이 모드는 기본 계정의 연락처 조회, 원격 이미지 설정 저장, 발신자 신뢰 저장, JMAP CID blob 조회를 실행하지 않는다. 외부 이미지는 기본 차단이며 현재 메일의 한 번 보기만 허용한다. 첨부는 이름/바이트 크기만 표시하고 다운로드와 인라인 이미지 미지원 상태를 명시한다. 별도 안전한 연결 계정 첨부 BFF가 필요하다.

모바일에서는 목록과 선택 본문을 전환하고 목록으로 돌아가는 버튼을 제공한다. 데스크톱은 목록/본문 2열이다. 모달 내부 계정/폴더 선택과 헤더는 고정하고 목록과 본문은 각각 가용 높이 안에서 스크롤한다. 공통 버튼/선택 상자/사용자 정의 Tooltip과 테마 토큰을 사용한다.

## 검증 및 남은 수용

- `test-linked-mail-viewer.mjs`: 실제 캐시 GET 함수의 경로/식별자/커서/잘못된 응답·HTTP 실패/abort, 10개 언어 초기 SSR과 자동 요청 없음. 조회 cleanup과 세대 키는 소스 구조 검사이며 실제 브라우저 race 수용 검증으로 주장하지 않는다.
- `test-linked-accounts.mjs`: 기존 계정 등록 화면의 10개 언어 SSR 회귀.
- 공유 HTML 관련 frame policy/resize/image policy/loading/sender settings 검사 통과. 격리 모드의 연락처·첨부·설정 guard도 검사했다. 실제 악성 HTML 실행/실제 CID 다운로드 검수는 아니다.
- 변경 범위 ESLint, `npm run check:locales` 10개 언어/3133키 통과.
- UI/공유 렌더러/번역 입력 변경 때문에 프로덕션 빌드를 새로 실행했다. `GXWEBMAIL_BUILD_DIR=.next-gmail-start-validation npm run build -- --webpack` 종료 0, TypeScript/408페이지/trace 확인. 현재 캐시 GET BFF 계약 검사도 통과했다. 배포나 브라우저 검수를 대신하는 증거는 아니다.

실제 외부 계정 등록·인증·LIST·동기화·메일 상태 변경·발송·운영 배포는 실행하지 않았다. 현재 사용자 페이지는 브라우저 보안 정책으로 직접 접근할 수 없으며 우회하지 않았다. 신규 모달의 실제 desktop/mobile·키보드·hydration/콘솔 검수와 외부 계정 캐시 실데이터 비교는 미완료다. 동기화 UI, 안전한 첨부 조회, 미확정 LIST의 서버 작업 영수증 기반 복구도 남는다. 전체 통합 목표 완료가 아니다.

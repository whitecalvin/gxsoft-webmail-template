# Icon preloading / initial SVG rendering — 2026-10-08

Purpose: eliminate the wrong/default icon → spinner → selected icon transition, not merely hide it.

## Implemented

- Package-derived SVG manifest: all 2,066 Lucide and 1,512 Phosphor icons. Generated by `node scripts/generate-mailbox-svg.mjs`; regenerate when installed icon packages change. The manifest is imported only through `mailbox-svg.server.ts` (`server-only`). Never accept user SVG or mail HTML as manifest contents.
- Root layout resolves stored cookie preferences before rendering and passes only the deduplicated, selected SVGs to the icon context. Selected SVGs render synchronously and remain the same through hydration; emoji remains inline text.
- Account/personal/system glyph wrappers no longer defer the common glyph component itself.
- Picker pointer entry, focus and touch start preload its first 80 previews and current selection. Package-tab intent preloads that tab's first 80 previews. Preview intent preloads individual files. Modules and in-flight requests are shared/deduplicated.
- Selection waits for its file to be ready before changing the displayed icon. Escape, close, unmount, a newer choice and default reset invalidate old pending selections.
- Existing account-scoped preferences and cookie bounds are preserved. No server identity, mail, permission or production configuration mutations.

## Still unverified / limitations

- This proves the registered SVG render path, not absence of every first-paint flash on every page/device. Physical mobile first-paint and reload observations have not been completed.
- SSR needs a preference present in the bounded cookie and the account identity available to the consuming component. A legacy browser-only preference or cookie entry evicted by its existing 3,000-character limit cannot be reconstructed by the server; this persistence boundary still needs separate completion.
- Selecting a previously unloaded package/search result can still show loading in the picker grid while its file downloads. The existing selected icon remains unchanged until loading succeeds.
- Frontend source/build only; no deployment or production restart.

React best-practices review informed selected-only RSC serialization and retained per-icon dynamic imports for browser previews instead of shipping the complete SVG manifest to the client.

# 편지함 표시 설정 연동

- 설정 > 받은편지함 및 읽기 > 표시할 편지함에서 기본/개인 편지함을 선택한다.
- 일반 설정의 inbox.hiddenSystemMailboxes 및 inbox.hiddenMailboxIds 계약을 사용한다. 계정별 저장 및 expectedRevision/불확실 결과 복구는 기존 SettingsProvider와 저장 바를 사용한다.
- root layout의 기존 인증된 일반 설정 SSR snapshot을 그대로 소비한다. 사이드바는 draft가 아닌 saved 목록으로 필터링한다.
- 개인 편지함 전체 목록, 검색, 규칙, 메일 조회/수신 및 데이터는 필터링하지 않는다. 표시 가능한 자식은 숨긴 부모 대신 상위 목록으로 승격한다.
- 시스템 메뉴는 기존 FOLDERS에 있는 항목만 선택 대상으로 표시한다. starred 계약은 지원하지만 기존 메뉴에 없는 중요 전용 항목을 새로 추가하지 않는다.
- 관련 8개 테스트 및 10개 언어 키/사용 검사 통과. 변경 코드 ESLint 및 프로덕션 빌드 통과(Build ID: H3xRQKDPYOvhQ191ey1lQ).
- 같은 브라우저 탭을 재확인해 실제 설정 화면, 기본 7개/개인 4개 목록 및 활성 체크박스를 확인했다. 전체편지함 선택 해제 시 저장 활성화·저장 전 메뉴 유지, 설정 영역의 취소 후 체크 복원·저장 비활성화를 확인했다. 초안만 변경/복원했으며 서버 저장 및 새로고침 영속성은 미검증이다. 운영 계정 설정/메일은 변경하지 않았다.
- 증거 화면: mailbox-visibility-settings-20261011.png. 브라우저 최초 탐색 시간초과는 후속 동일 탭 조회로 복구됐다.
- 기존 worktree의 다른 파일 및 WorkspaceSidebar 기존 공백 오류는 변경하지 않았다.

## 승인된 실제 저장·복원 검증

- 2026-10-11 사용자 승인 후 미저장 변경 없음과 보관함 표시 상태에서 시작했다.
- 보관함 체크 해제·저장 후 컨트롤 재활성화, 사이드바 보관함 항목 0개를 확인했다.
- 새로고침 후에도 보관함 체크 해제 및 메뉴 항목 0개가 유지됐다.
- 보관함 체크·저장으로 복원하고 새로고침 후 체크 활성 상태 및 메뉴 항목 1개를 확인했다. 복원 저장 뒤 저장 버튼은 비활성 상태였다.
- 메일 이동/삭제/발송이나 다른 설정 변경은 수행하지 않았다. 이 증거는 보관함 시스템 항목의 정상 저장·새로고침·복원 경로에만 해당한다. 개인 편지함 저장, 계정 간 격리 및 실패/충돌/불확실 결과는 별도 검증이다.
- 복원 화면: mailbox-visibility-restored-20261011.png. 전체 페이지 캡처 실패 후 현재 뷰포트 캡처만 재시도했다.
- 앱 입력은 변경하지 않아 통과한 테스트·번역·빌드를 재실행하지 않았다.

# 개별 규칙 적용 (2026-10-11)

## 구현

- 규칙 목록 각 항목의 ▶ 아이콘에서 공통 적용 모달을 연다. 제목에 선택한 규칙 이름을 표시한다.
- 저장된 `rules[].id` UUID와 전체 목록 개정을 계획 요청에 전달한다. 전체 적용은 `ruleId`를 생략한다. 미저장 변경사항, 비활성 규칙 및 불확실한 저장 결과가 있으면 개별 적용을 차단한다.
- BFF는 계획 요청에서만 선택 ID를 허용한다. 실행 단계는 저장된 plan ID와 기존 idempotency key를 사용하며 선택 범위를 변경할 수 없다.
- 미리보기 응답의 편지함·개정·규칙 ID를 확인하고, 실행 및 결과 조회도 기존 계획의 동일한 범위와 일치해야 한다. 구버전 서버가 전체 범위를 반환하더라도 개별 적용 성공으로 처리하지 않는다.
- 미확정 실행은 동일 계획의 결과를 조회하며 새 계획 생성 및 편집을 잠근다. 실행 전 공통 확인 창과 휴지통 이동 동의를 유지한다.
- 기존 200통 / 16 MiB 제한은 그대로다. 계획 생성은 메일 변경은 아니지만 서버 계획 저장이 발생한다.

## 검증 경계

`scripts/test-mail-rule-application.mjs`의 합성 요청은 전체/개별 범위, 미저장 ID 거부, 실행 요청의 범위 변경 거부, 잘못된 범위의 영수증 거부와 결과 불확실 시 잠금·동일 키 보존을 검사한다. `scripts/test-mail-rule-sidebar.mjs`는 열 개 언어의 아이콘 상태와 미저장·비활성·잠금 상태를 서버 렌더링으로 검사한다.

로컬 브라우저에서 저장된 github/chatgpt의 개별 모달 제목과 편지함 선택, 전체 적용 버튼 잠금 및 닫기 동작을 확인했다. 닫은 뒤 github의 적용 버튼으로 포커스가 복원되는 것도 실제 DOM에서 확인했다. 실제 계획 생성·기존 메일 실행, 운영 배포 및 DB 변경은 수행하지 않았다. 실제 적용 성공의 검증은 승인된 합성 메일 범위에서 별도로 필요하다.

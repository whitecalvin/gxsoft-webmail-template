# 로그인 본문 읽기 제한

## 변경 범위

`POST /api/mail/session`이 `request.text()`로 본문 전체를 읽은 후 길이를 검사하던 경로를 서버 전용 `lib/tastemail/login-body.ts`로 교체했다.

- 기존 4096 UTF-16 코드 단위 제한을 유지하고, 읽는 도중에도 길이를 확인한다.
- UTF-8 스트림은 16 KiB를 넘으면 중단한다. 유효한 4096 코드 단위 문자열을 바이트 수 때문에 거부하지 않는 상한이다.
- 본문 읽기 전체에 5초 제한을 적용한다. 청크마다 제한 시간을 연장하지 않는다.
- 요청 신호가 중단되면 읽기를 종료한다. 스트림 취소 완료가 지연되어도 오류 응답을 무기한 기다리지 않는다.
- 잘못되거나 끝이 잘린 UTF-8, JSON 파싱 실패, 과대 본문, 시간 초과는 기존 `400 invalid_request` 응답으로 처리한다. 이런 요청에는 인증 API를 호출하거나 쿠키를 설정하지 않는다.

사용자 이름·비밀번호·MFA 검증, Origin/TLS 검사, 인증 API 주소, 응답 형식 및 HttpOnly 쿠키 정책은 변경하지 않았다. TASTEMAIL Rust `LoginRequest`의 `username`, `password`, `mfaCode` 계약을 소스에서 확인했다. 서버 설정·DB·서비스 재시작·실제 로그인 및 메일 변경은 수행하지 않았다.

## 검증

`scripts/test-session-route-boundary.mjs`는 실제 라우트와 NextResponse를 실행하되 인증 서버는 합성 응답으로 대체한다. 외부 네트워크는 사용하지 않는다.

검증 범위: ASCII·한글·이모지 길이 경계, 멀티바이트 청크 분할, 과대 바이트 스트림, 잘못된 UTF-8 및 불완전한 UTF-8, 사전/진행 중 abort, 실제 5초 읽기 제한, 끝나지 않는 취소 처리, 인증 호출 차단, 기존 MFA·쿠키·만료·권한·오류·로그아웃 처리.

이 테스트에는 별도의 개발/운영 실행 모드가 없다. 운영 번들 및 타입 검증은 Next.js production build로 별도 확인한다. 실제 운영 인증과 브라우저 GUI 검증을 대체하지 않는다.

2026-10-11 결과: 세션 라우트 합성 회귀 테스트 통과, 변경 파일 ESLint 통과, 해당 라우트 `git diff --check` 통과, `.next-gmail-start-validation` 분리 출력 디렉터리의 webpack production build 및 타입 검증 통과(408개 정적 페이지 생성). 의존성·UI·번역은 변경하지 않아 관련 전체 회귀는 반복하지 않았다.

전체 연동 완료 여부는 [현재 인수 검증표](live-integration-acceptance-20261011.md)와 별도로 판단한다. 본 변경은 요청 입력 경계만 검증했으며 실제 서버 기능의 동작 증거는 아니다.

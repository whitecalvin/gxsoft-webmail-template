# 임시보관함 메일 계속 작성

## 실제 신규 초안 검수

- 후속 닫기 검수: 저장된 초안의 변경 없는 닫기와 되돌리기는 확인창 없이 닫히고 실제 수정 시에는 공통 확인창을 유지하도록 수정했다. 합성/실제 UI 근거는 saved-draft-close-20261010.md 참조. 이전 검수의 '추가 저장하지 않고 닫기'에서 나타난 불필요한 확인창은 이 변경으로 해결됐다.

- 승인된 신규 합성 메일만 사용하는 UI 검수에서 상세 어댑터가 모든 메일을 inbox로 투영해 계속 작성의 초안 안전 검사가 거부하는 문제를 발견했다. `loadLiveMailDetail`에서 Email/get과 Mailbox/get을 같은 JMAP 요청으로 조회하고 실제 소속으로 drafts/sent/trash/inbox/archive/spam/custom을 판정하도록 수정했다. 소속 없는 결과는 실패하며 휴지통 소속을 초안보다 우선한다. 초안 검사나 계정 발신자 일치 조건을 제거하지 않았다.
- 신규 QA 제목 `GXWebMail-continue-draft-QA-1791614835040` 한 통을 만들고 v1 본문 임시 저장 → 목록 메뉴에서 계속 작성 → v1 전체 본문 확인 → v2 본문 수정 및 임시 저장 → 페이지 새로고침 → 같은 제목 한 통 확인 → 계속 작성으로 v2 보존을 확인했다. 임시보관함 총수는 4에서 5로 증가했으며 재저장 후 같은 QA 제목은 한 통이다. 수신자를 추가하거나 발송하지 않았다. 기존 사용자 메일은 변경하지 않았다.
- 마지막 검수 작성창은 추가 저장하지 않고 닫았다. 저장된 v2 QA 초안 한 통은 남아 있다. 임시 검수 탭을 닫았고 콘솔 error 0. `continue-draft-resave-20261010.png`는 신규 합성 메일의 작성창만 기록한다.
- 이번 검수는 수신자 없는 일반 합성 본문 초안의 계속 작성·재저장·보존을 증명한다. 실제 첨부/CID·복잡한 HTML·발송·계정 전환 검증까지 증명하지 않는다. 실제 소속별 상세 판정 및 소속 누락/휴지통 우선 차단 합성 회귀 검사와 변경 파일 ESLint를 통과했다.
- 상세 소속 판정 수정 후 최종 production build55312 exit0. 컴파일·TypeScript·393페이지 생성·최종 빌드 마무리 통과. 이후 검수 문서 변경만으로 앱 빌드를 반복하지 않는다.

- 보내는 사람 주소가 로그인 계정 주소와 같은 초안만 계속 작성할 수 있다. 주소는 앞뒤 공백과 대소문자를 정규화해 비교한다. 목록 메뉴 표시와 실행 진입, 전체 상세 조회 후, 편집기 열기에서 동일 조건을 확인한다. 다른 발신자·빈 주소·상세 조회 후 발신자 불일치 회귀 검사 통과. 서버의 저장 권한 검사를 대신하는 조건은 아니다.

- `MailList`의 공통 actionItems에 초안 전용 ‘메일 계속 작성’을 추가했다. desktop 우클릭/더보기 및 모바일 ActionSheet가 같은 항목을 사용한다. 10개 언어 라벨을 추가했다.
- `useContinueDraft`는 기존 same-origin 상세 조회 BFF와 엄격한 응답 검사를 사용한다. 미리보기 대신 전체 본문·HTML·수신자·첨부/CID·기존 previousDraftId를 작성창에 전달한다. 클릭 자체는 초안을 저장하거나 발송하지 않는다.
- 중복 요청/변경 중/미확정 변경을 차단하고, 계정·편지함 변경/언마운트 시 요청을 취소한다. 실패 시 작성창을 열지 않는다. 보존하기 어려운 HTML은 기존 공통 ConfirmDialog로 일반 텍스트 편집을 확인하며 같은 계정/화면 범위의 확인만 사용한다.
- 합성 실행 검사에서 전체 상세 보존, 초안 전용 메뉴, 쓰기 잠금, 실패, HTML 확인, 중복 방지, 취소된 응답 무시 통과. 변경 컴포넌트/검사 ESLint 및 10개 언어3054키 일치 통과. 실제 사용자의 초안 편집·저장·발송은 검증하지 않았다.

# 계정별 라벨 설정

## 구현

- 설정의 라벨 항목을 실제 서버 CRUD에 연결했다. 이름·색상·수정·삭제, 최대 256개, 빈 목록과 재확인 UI를 제공한다.
- 일반 편지함과 분리된 표시 메타데이터 관리다. 이 작업은 메일 적용·메일 이동·삭제 기능을 추가하지 않는다.
- 연결 규격: `D:/works/projects/GXSOFT/TASTEDEV/resources/guides/dev-01/tastemail-labels-20261008/API.md`.
- `/api/mail/labels`의 GET/POST 및 `/api/mail/labels/[id]`의 PATCH/DELETE를 인증된 서버 API `/api/user/labels`로 전달한다.
- 사용자/계정 ID는 브라우저 입력으로 전달하지 않으며 기존 세션 인증을 사용한다. 쓰기는 same-origin 확인, 8KiB 제한, 추가 필드·UUID·revision·이름·색상 검증을 거친다.
- 응답은 private/no-store, 알려진 라벨 필드만 반환한다. UUID와 keyword의 일관성을 검사하고 서버 오류 상세·토큰을 노출하지 않는다.
- 저장 응답의 revision·대상·다른 라벨 보존을 확인한 뒤 성공 표시한다. 응답 유실·충돌이면 변경을 잠그고 목록 확인을 요청한다. 자동 재전송하지 않는다.
- 계정 변경 시 UI를 초기화하고 이전 계정 조회 결과를 폐기한다. 폼 변경 시 이탈 경고, 삭제 시 공통 확인 모달을 사용한다.
- 기존 36px/40px 공통 컨트롤을 재사용한다. 10개 언어 메시지를 추가했다.
- 서버에 API가 없으면 운영 API/마이그레이션 적용 확인 안내를 표시한다. 시연 데이터나 가짜 성공을 제공하지 않는다.

## 경계

서버 API 소스와 마이그레이션 0062는 서버 채팅에서 구현되었다. 이 웹메일 작업은 서버 배포·운영 DB 마이그레이션·실제 라벨 저장·메일 변경을 하지 않는다. 운영 적용 상태를 이 문서만으로 확인할 수 없다.

## 검증

`scripts/test-user-labels.mjs`는 합성 데이터만 사용한다. 계약/입력/색상/keyword/응답 보존, 서버 adapter 실패/충돌/불확실, 세션/same-origin route, 실제 UI JSX의 빈 목록·수정·미적용·저장 경합·응답 유실을 검사한다.

실제 로그인 계정의 저장·삭제 및 브라우저 시각 검증은 미실시다.

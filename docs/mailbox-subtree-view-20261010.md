# 상위 편지함 통합 조회

- 사용자 편지함을 선택하면 자신과 `이름/` 접두사를 가진 모든 하위 사용자 편지함을 포함한다. 예: 개발 선택 시 개발, 개발/Github, 개발/ChatGPT 및 더 깊은 하위 메일도 함께 조회한다. 기본 편지함과 개발팀 같은 유사 접두사는 제외한다.
- JMAP Email/query의 OR 조건을 사용하므로 서버에서 단일 날짜 정렬, 고유 메일 ID 조회, 총수 계산 및 페이지 분할을 수행한다. 각 편지함의 첫 페이지를 클라이언트에서 합치지 않는다. 기존 메일 이동·복사·DB 변경은 없다.
- 통합 목록에서 메일을 다른 편지함으로 옮기는 경우 실제 소속 하위 편지함을 출발지로 지정한다. 선택한 상위 편지함에 실제로 속하면 해당 소속을 우선한다. 보낸편지함 같은 기본 편지함을 하위 출발지로 잘못 선택하지 않는다.
- 합성 회귀 검사: 하위/손자 포함, 유사 이름/기본 편지함 제외, 하위 없는 단일 조건, 실제 하위 이동 출발지 통과. 변경 파일 ESLint 통과. 실제 기존 메일 변경 검증은 수행하지 않았다.
- diff-check에서 mail-context.tsx의 기존 공백 줄 경고가 발견되었으며 이번 수정과 무관한 부분은 보존했다.

## 실제 화면 검수

- 인증된 별도 임시 탭에서 개발 선택 시 헤더 8통과 8개 목록 항목을 확인했다. Github 선택 시 8통이며 개발 목록과 모든 항목/순서가 일치했다. ChatGPT 선택 시 0통과 빈 목록을 확인했다. 따라서 현재 데이터의 개발 자체 0통 + Github 8통 + ChatGPT 0통 통합 조회가 실제 화면에서 확인됐다.
- 메일 상세 열기, 읽음·별표·이동 등 상태 변경 없이 목록 탐색만 수행했다. 메일 제목/본문은 출력하거나 산출물에 기록하지 않았다. `mailbox-subtree-header-20261010.png`는 제목/본문을 제외한 개발 목록 헤더만 기록한다. 검수 탭을 닫았다.
- 해당 임시 탭 콘솔 error 0, hydration error 0. 여러 비어 있지 않은 하위 편지함과 다중 페이지 실데이터 수용 검증까지 증명하는 결과는 아니다.
- 코드 최종 production build72419 exit0: 컴파일, TypeScript, 393페이지 생성과 빌드 마무리 통과. 이후 변경은 검수 문서뿐이므로 동일 앱 빌드를 반복하지 않는다.

# 설정 메일 규칙 GUI 개선

## 범위

- 기존 테마·공통 Input/Button/CustomSelect/Switch와 서버 저장 계약을 유지했다.
- 목록·편집 분할 구조, 순서 안내, 빈 상태, 이름/종류 한 줄 정렬, 활성 상태 설명을 정리했다. 모바일에서는 한 열로 배치된다.
- 저장/취소와 미저장 상태는 하단 sticky 작업 영역으로 통합했다.
- 일반 편집은 발신자 일치/제목 포함 조건, 유지/읽음/중요 표시, 후속 규칙 중단을 지원한다. 조건이 없으면 전체 메일에 적용된다고 안내한다.
- 해석 가능한 템플릿만 일반 편집기에 표시한다. 기존 임의 Sieve, 편지함 이동/부재중 등 지원하지 않는 동작은 원본을 보존하고 고급 편집을 펼친다. 자동 변환·저장하지 않는다.
- 메일 목록에서 만든 발신자 초안도 같은 일반 편집기로 표시된다.

## 검증

- 개발 검사 136개 통과: 관련 4개를 먼저 실행하고 동일 입력 결과를 재사용하여 나머지 132개를 실행했다.
- 새 일반 규칙 검사: 72개 조합 왕복, 문자열 이스케이프, 플래그/require, 원본 변경 감지, 합성 React 렌더·비활성 상태·렌더 중 쓰기 없음.
- 관련 운영 모드 일반 편집/저장 경합 검사 2개 통과.
- 전체 ESLint은 오류 없이 통과했다. 새 테스트 대역의 미사용 변수 경고 2개는 테스트 파일만 수정한 뒤 해당 파일 린트와 개발·운영 검사를 재개해 해소했다. 이 테스트 전용 수정은 앱 빌드를 무효화하지 않는다.
- 10개 언어 3006키·1186개 리터럴 호출 검사 통과.
- 직전 Turbopack CSS 프로세스 실패에 대한 검증된 대체 경로인 Webpack 운영 빌드 사용: `.next-folder-drag`, 컴파일/TypeScript/380페이지 생성/최적화, 종료 코드 0. 실행 중인 개발 서버 출력은 사용하지 않았다.

## 미실시

로그인된 실제 브라우저에서 모바일/데스크톱 수동 시각 검증, 실제 계정 규칙 변경·저장 왕복, 운영 배포 및 DB 변경은 실행하지 않았다. 합성 렌더와 로컬 빌드는 이 실검증을 대체하지 않는다.

## 첨부 화면 피드백 후 보정

- 설정 아코디언에서는 중복 제목 대신 설명만 표시한다.
- 빈 상태는 단일 안내와 단일 추가 버튼으로 통합하고, 빈 목록/편집 패널과 의미 없는 비활성 저장 버튼은 표시하지 않는다.
- 변경사항이 있을 때만 저장 작업 영역을 표시한다. 마지막 규칙 삭제 후에도 저장/취소를 유지한다.
- 개정·전체 활성 상태는 도움말로 옮겼으며 모드 전환 확인은 저장 확인 경로에서 유지한다.
- 설정 메인 페이지의 메일 규칙만 누락됐던 공통 패널 여백을 적용했다. 개별 설정 페이지와 메일 목록 모달에는 이 외부 여백을 중복 적용하지 않는다.
- 실제 JSX를 합성 데이터로 렌더링하는 새 검사에서 빈 상태/목록/로딩, 중복 제목·추가 버튼 제거, 최종 삭제·미확정 저장 복구, 패널 여백을 검증했다. 개발·운영 모드 통과.
- 개발 검사 137개 통과(관련 3개 결과 재사용 + 나머지 134개). 전체 ESLint 통과 후 마지막 패널 여백/검사 변경은 해당 파일 린트와 관련 렌더 검사만 재개했다. 번역·서버 저장 입력은 바꾸지 않았다.
- 최종 패널 여백 변경이 빌드 입력을 무효화하여 빌드 단계만 재개했다. Webpack 운영 빌드 컴파일/TypeScript/380페이지 생성/최적화 종료 코드 0. 이전 입력의 빌드 성공을 최신 입력의 증거로 사용하지 않았다.

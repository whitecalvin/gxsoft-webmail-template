# 검색 화면 언어·화면 회귀 관찰 — 2026-10-08

## 범위

실제 로그인된 로컬 Next.js 개발 서버 `http://127.0.0.1:7540`에서 별도 임시 탭을 사용했다. 키워드 없는 `/[locale]/search` 화면만 확인했으며 메일 목록·본문, 인증정보, 저장 설정은 변경하지 않았다.

- 언어: ko, en, de, es, fr, it, pt, ja, zh, zh-hant.
- 데스크톱: 1280 × 900.
- 모바일: 390 × 844의 브라우저 viewport. 실제 모바일 기기 검증은 아니다.
- 각 화면에서 검색 입력에 ArrowRight 키를 보내 포커스 가능 여부를 확인하고, DOM 렌더링과 브라우저가 수집한 error/warn 로그를 관찰했다.
- 최초 필터 탐색은 명시적 `[role=group]`만 검색해 false를 반환했다. 실제 의미 구조가 `<fieldset><legend>`인 것을 확인하고 측정 기준을 바로잡아 전체 20개 화면을 측정했다. 초기 false를 UI 결함으로 판정하지 않았다.

## 관찰 결과

| 항목 | 데스크톱 10개 언어 | 모바일 10개 언어 |
| --- | --- | --- |
| HTML lang 및 검색 제목 | 해당 언어로 표시 | 해당 언어로 표시 |
| 검색 필터 fieldset·legend | 표시 | 표시 |
| document scrollWidth | viewport 1280과 일치 | viewport 390과 일치 |
| 표시 중인 본문 입력·버튼의 좌우 화면 경계 초과 | 0 | 0 |
| 수집 로그의 hydration 관련 오류 | 0 | 0 |
| 수집 로그의 error 항목 | 0 | 0 |

중국어 번체 모바일 화면의 스크린샷도 확인했다. 검색 입력 아래에 필터 제목, 기간·폴더, 시작일·종료일, 첨부·정렬 항목이 2열로 표시됐고 화면 오른쪽으로 넘치지 않았다. 날짜 필드의 기본 입력 표시 형식은 브라우저/운영체제의 지역 설정에 영향을 받으며, 이 관찰은 모든 기기의 날짜 선택 UI를 검증한 것이 아니다.

## 한계 및 남은 게이트

- 관찰 시간 내 수집 로그에 오류가 없다는 증거이며, 모든 시점·모든 경로의 콘솔 무오류 보장은 아니다.
- 빈 검색 화면의 반응형·번역 렌더링에 한정된다. 실제 키워드·날짜 필터 요청의 서버 데이터 일치, 상세 본문, 다른 페이지, 드롭다운 모든 옵션, 키보드 접근성 전체 검증은 별도다.
- 수정 후 실계정 다중 편지함 이동, MFA/권한 거부/유효 세션 만료/통제 장애 복구 및 전체 기능 수용 검증은 완료하지 않았다.
- 앱 소스·빌드 입력을 바꾸지 않아 이전 빌드·단위 검사를 반복하지 않았다. 문서 및 체크포인트 JSON만 갱신하고 JSON 구문을 확인했다.
- 임시 viewport는 원래대로 복원하고 검증 탭을 닫았다. 재발송·이동·삭제·운영 서버 설정 변경·커밋·푸시는 하지 않았다.

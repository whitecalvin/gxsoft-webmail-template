# TASTEMAIL 관리자 기능 이식 기준

### 공용 편지함 취소의 초안 범위 — 2026-10-13

- 원본 공용 편지함의 독립 draft/권한 취소 경계를 대조했다. 생성 취소는 입력이 바뀌었을 때 공통 확인 후 기본 입력으로 복원하고, 권한 취소는 현재 편지함의 변경만 확인 후 서버 스냅샷으로 복원한다. 다른 편지함의 캐시된 초안과 원래 개정은 유지한다. 확인 창 취소는 입력을 바꾸지 않으며 busy 상태에서는 실행하지 않는다.
- 생성 이름의 HTML maxLength를 기존 서버 계약/원본과 동일한 200자로 맞췄다. 별도 확인 창이나 새로운 저장 API를 추가하지 않는다.
- 실제 선택/복원/취소 콜백과 독립 초안·closed 계약/BFF·중복/불확실한 저장 경합 검사 36개 및 변경 파일 ESLint·프로덕션 빌드 410페이지 exit 0을 확인했다. 합성 GUI에서 공통 확인 창 표시, 계속 편집 시 폼 유지, 폐기 승인 시 생성 폼 숨김 및 재열기 시 빈 주소/10 GiB 기본값 복원을 확인했다. 비어 있지 않은 주소는 브라우저 관찰에 마스킹돼 정확한 문자열 동등성은 UI에서 증명하지 못했으며 실제 callback 검사로 분리한다. 실제 공유 생성/권한 변경은 하지 않았다.
- 생성 취소가 페이지를 떠나는 동작은 아니므로 공통 미저장 확인 설명을 10개 언어에서 일반적인 변경 폐기 설명으로 보완했다. 기존 ConfirmDialog와 OS 버튼 순서를 유지한다. 공통 초안 보호 검사 7개·10개 언어 키 검사·TypeScript/프로덕션 빌드 410페이지 exit 0을 확인했다.
- 수정된 산출물의 합성 GUI에서 용량을 10→11 GiB로 편집해 확인 창의 새 설명을 확인했다. 계속 편집 후 정확히 11 유지, 폐기 승인/폼 재열기 후 정확히 10 복원을 DOM으로 검증했다. 이메일/비밀번호 입력이나 실제 생성/권한 저장은 하지 않았다. React/hydration/번역 오류 패턴 0개, 증거 `admin-shared-cancel-20261013.jpg`. 임시 탭과 검수 서버 정상 종료를 확인했다.
- 원본의 모든 공용 편지함 동시 카드 표시까지 구현된 것은 아니며 전체 관리자 이식 완료를 의미하지 않는다.

### 관리자 첫 조회 SSR 및 hydration 중복 제거

- 보고서만 초기 서버 데이터를 받던 구조를 관리자 section 공통 초기 loader로 확장했다. 기존 관리 리소스·공용 편지함 목록·격리 목록은 HttpOnly 세션과 기존 닫힌 서버 계약으로 조회한 데이터/오류를 Server Component에서 전달한다. 도메인 선택이 필수인 DKIM/도메인 테마는 대상 선택 전에 요청하지 않는다. 신규 API나 시연 목록을 추측하지 않는다.
- 공통 초기 조회 gate는 같은 첫 조건의 StrictMode 재실행에서도 브라우저 재조회를 생략한다. 새로고침/검색/cursor/개정이 한 번 변경되면 초기 스냅샷 재사용을 끝내므로 첫 페이지로 돌아와도 오래된 초기 데이터로 대체하지 않는다. 초기 권한/서버 오류도 정상 빈 목록으로 바꾸지 않는다.
- 초기 section scope가 일치하는 데이터만 클라이언트에 전달한다. 기존 개별 상세 조회·편집 초안·저장 확인·서버 개정·경합 보호는 유지한다. 보고서의 기존 SSR 경로는 같은 loader를 사용하며 기능을 축소하지 않았다.
- 초기 gate/전체 section loader/Server Component 인계/실제 클라이언트 SSR·중복 생략/실제 refresh effect 검사 5개, 보고서 계약/10개 언어 SSR 2개, 기존 mutation 경합 18개 통과. 신규 refresh 검사 fixture의 adminFilterKey 누락을 보완하고 해당 실패 검사만 재개했다. 변경 파일 ESLint와 프로덕션 webpack 빌드 408페이지 통과.
- `verify-admin-operations.mjs --initial-ssr` 실행: 사용자·그룹·공용 편지함·격리·큐·정책·보고서 7개 페이지에서 RSC script를 제외한 실제 첫 HTML에 표/정책 값이 포함됨을 확인했다. 불완전 정책은 첫 HTML에 기본값으로 표시되지 않는다. 합성 루프백 검사이며 운영 계정 변경은 하지 않았다.
- 같은 완료 빌드를 합성 브라우저에서 사용해 초기 그룹 목록의 이름/구성원, 초기 데이터로 편집 진입·자동 포커스·취소를 확인했다. hydration/Minified React/invariant 패턴 0개. 증거 `admin-initial-ssr-20261012.png`. 생성 탭과 임시 서버를 정상 정리했다. 전체 관리자 이식 및 운영 수용 완료를 의미하지 않는다.

### 스팸 정책 조회의 기본값 대체 차단

- Rust `AdminSpamPolicyResponse`/`spam_policy_response` 및 `validate_spam`을 대조했다. 기존 범용 singleton projection은 revision만 필수였고 누락 필드가 `prepareAdminCommand`에서 false/0/빈 목록으로 채워질 수 있었다. 스팸 정책 조회를 저장과 같은 필수 유형·숫자 범위·순서·목록 경계로 검증하도록 수정했다.
- source는 configuration/database 문자열, revision은 음수가 아닌 안전한 정수, updatedAt은 명시적 null 또는 유효한 시각 문자열이어야 한다. nullable 임계값의 명시적 null, 점수 0, enabled false, 빈 목록은 그대로 보존한다. 누락은 이러한 정상 값과 구분한다. 계약 외 값과 expectedRevision은 조회 UI에 노출하지 않으며 배열은 독립 복사한다.
- 정책 필드/메타데이터의 전수 누락·유형·경계 검사, 실제 loader/GET route 검사 및 기존 관리/쿼리 검사 총 19개, 변경 파일 ESLint, 프로덕션 webpack 빌드 408페이지 통과. 새 fixture의 URL 개수 임계값을 0으로 둔 오류를 1로 수정하고 해당 실패 검사만 재개했다.
- 완료된 빌드에서 `verify-admin-operations.mjs --spam-policy` 실행: 컴파일 BFF의 닫힌 projection, null 유지, private no-store, 401/403/429 유지 및 불완전 정책의 502/unavailable을 확인했다. 합성 루프백 조회 검사이며 운영 정책 저장·DB 변경은 수행하지 않았다.

# 개인 폴더·편지함 이동 — 2026-10-08

## 동작

- 왼쪽 메뉴의 개인 폴더·편지함 이름/손잡이: 데스크톱 HTML drag and drop.
- 모바일 손잡이: pointer capture 기반 터치 드래그, 8px 이동 임계값.
- 손잡이를 클릭/터치하거나 키보드로 선택한 뒤 목적지 이동 버튼을 눌러도 동일한 이동 경로를 사용한다. Escape로 취소한다.
- 생성한 폴더·편지함 컨텍스트 메뉴의 `이동`도 같은 목적지 선택 모드를 연다. 목적지 폴더의 화살표 또는 최상위 이동 버튼을 눌러 확정한다. 메뉴 선택만으로는 서버 쓰기를 수행하지 않는다. pending/uncertain 및 계정 미확정 상태에서는 이동 메뉴를 비활성화한다.
- 이동 목적지는 폴더 또는 최상위만 허용한다. 생성 종류가 편지함인 항목은 목적지가 될 수 없다.
- 시스템 편지함, 자기 자신/하위 경로, 동일 부모, 이름 충돌, 255 UTF-8 byte 초과 경로, 외부 drag payload를 차단한다.
- 서버 응답 전에 트리 경로를 낙관적으로 변경하지 않는다. 중복 요청은 잠금으로 막으며 불확실한 응답은 기존 쓰기 제한을 유지한다.
- 이동해도 ID가 유지되어 계정별 아이콘 및 활성 편지함 연결이 유지된다. 활성 하위 편지함 이름도 갱신하되 나중에 이동한 화면을 덮어쓰지 않는다.

## 서버 연결

기존 `/api/mail/folders` → TASTEMAIL `POST /api/personal-folders`, `operation: rename`을 재사용한다. TASTEMAIL 소스에서 이름과 하위 경로를 한 트랜잭션으로 변경하는 동작을 확인했다. 루트 및 모든 하위 ID/이름의 응답을 확인한 뒤 목록을 갱신한다. 서버 수정·배포나 DB 변경은 수행하지 않았다.

폴더/편지함의 생성 종류는 기존 계정별 UI preference를 사용한다. SSR 초기 preference와 클라이언트 저장값을 공유하며, 종류가 없는 기존 개인 항목은 기존 UI와 동일하게 폴더로 취급한다. 서버에 별도의 종류 검증 기능을 추가했다는 의미는 아니다.

## 검증

통과: 드래그/터치 실제 컴포넌트 이벤트의 합성 fixture 테스트, 목적지/순환/충돌/길이 제한, 중복 요청 및 불확실 응답, 하위 경로 수신 확인, 활성 하위 편지함과 화면 전환 race, 기존 폴더 트리/사이드바/관리 UI 테스트, 10개 언어 catalog 및 사용 검사, 변경 범위 ESLint.

프로덕션 빌드 통과: 별도 `.next-folder-drag` 출력, TypeScript 및 378개 페이지 생성 완료, exit 0. 개발 서버 출력 디렉터리는 변경하지 않았다.

미검증: 실제 모바일/브라우저 드래그, 운영 서버 실제 편지함 이동. 기존 사용자 편지함을 검증용으로 생성·이동·삭제하지 않았다. Node fixture 테스트는 별도 Debug/Release 구분이 없어 중복 설정을 만들지 않았다.

React 점검 스킬의 상태/참조 분리 원칙을 적용했다. 화면에 쓰이는 선택 상태는 React state, 터치 좌표·요청 잠금은 ref로 관리한다.

## 드래그 시작 실패 수정

사용자 재현 보고 이후 손잡이에 연결된 `onPointerCancel={drag.cancel}`이 정상 HTML dragstart 직후 선택을 지우는 결함을 발견했다. HTML 표준의 drag 처리 모델도 dragstart 뒤 pointercancel을 발생시킨다: https://html.spec.whatwg.org/multipage/dnd.html#drag-and-drop-processing-model

실제 손잡이 JSX에 연결된 이벤트를 사용하는 `dragstart → mouse pointercancel → drop` 합성 회귀 테스트가 수정 전 실패했고 수정 후 통과했다. 마우스 pointercancel은 무시하며 실제 터치 세션 취소만 해제한다. 터치 이동 중 native dragstart가 개입하지 않게 제한했다. 아이콘을 포함한 행에도 native drag 이벤트를 연결했다.

수정 후 드래그 회귀/사이드바 SSR 테스트 및 변경 범위 ESLint 통과. 변경된 TSX 때문에 프로덕션 빌드만 재실행했으며 `.next-folder-drag` TypeScript/378개 페이지 생성 exit 0. 변경하지 않은 서버 계약·번역 검사는 앞선 통과 결과를 재사용했다.

브라우저 임시 탭에서 네 개 개인 항목의 행 및 손잡이 `draggable=true`, 활성 상태, 콘솔 오류 없음 확인. 기존 사용자 편지함은 실제 드롭하지 않았으며 임시 탭은 닫았다. 실제 서버 이동 및 모바일 물리 드래그는 여전히 미검증이다.

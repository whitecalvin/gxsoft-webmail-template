# 만료 후 로그인 안내 — 2026-10-13

실제 만료 검수에서는 접근이 차단됐지만 로그인 페이지에 만료 사유가 남지 않았다. 서버 페이지 인증401과 client 세션 재검사401은 닫힌 표시값 `reason=session-ended`로 로그인 화면에 연결한다. 무쿠키 최초 방문은 기존 로그인 화면을 유지한다. 로그인 페이지 자체의 기존 쿠키 조회401도 안내하며403·429·5xx·불명 응답을 만료로 오인하지 않는다.

쿼리는 표시용 불리언 하나만 전달하고 인증/리디렉션 목적지에는 쓰지 않는다. 유효한 서버 세션은 해당 쿼리가 있어도 기존 편지함으로 이동한다. 토큰·시각·UUID는 URL이나 client props에 추가하지 않는다. 기존10언어 `liveService.unauthorized` 문구를 서버 초기 렌더부터 표시한다. Next.js 스킬에 따라 Promise searchParams와 서버/클라이언트 경계를 유지했다.

## 증거

- 실제 로그인 페이지/컴포넌트 검사2개: 닫힌 query, 익명/401/403/429/5xx/불명/유효한 세션 분기,10언어 SSR 안내와 일반 로그인 구분.
- 변경 영향의 기존 세션 gate·페이지 캐시·로그인 중복 제출/MFA handler 검사를 각1회 통과. 전체 lint 종료0. 이후 추가된 운영 검증 스크립트만 별도 lint했다.
- 운영 빌드420페이지 통과(BUILD_ID `wJ42yUfE3exK277KtcFNb`). 실제 Next start와 격리된 loopback upstream에서10언어 최초 HTTP HTML 안내, 익명 구분, 합성 invalid cookie401 안내를 확인했다. 운영 서버에는 합성 요청/인증을 보내지 않았다.
- 격리 운영 빌드 브라우저에서 한국어 안내 표시, 모바일390px 가로 넘침 없음, console warning/error 없음. [화면 증거](session-login-notice-20261013.jpg).
- 실서버 현재 계정은 다시 로그인된 상태였고 로그인 URL에 표시 query가 있어도 편지함으로 정상 이동했다. 재만료/로그아웃은 실행하지 않았다. 실제 만료는 [직전 승인 검수](session-expiry-live-20261013.md), 추가 안내 화면은 위 격리 검수로 구분한다.

브라우저 탭을 종료하고 viewport를 원복했다. fixture의 stdin이 닫혀 정상 종료 입력을 보낼 수 없어 정확한 Node 부모/자식 PID와 commandline을 확인한 뒤 이 시험 프로세스 두 개만 종료했다. 다음 실행부터 browser fixture에는 열린 TTY가 필수다. 스크립트 제어 변경뿐이라 앱 빌드를 반복하지 않았다. MFA 실제 등록·인증과 외부 계정 수용은 별도 승인/실제 계정 검증이 남아 있다.

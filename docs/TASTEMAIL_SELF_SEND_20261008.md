## 직접 관찰한 결과

1. 임시저장 완료 후 임시보관함에서 합성 초안 한 건을 확인했다.
2. 초안 재편집에서 제목·본문·첨부 보존과 자기 주소 수신 칩을 확인했다.
3. 보내기를 한 번 클릭한 후 `발송 대기열에 접수했습니다` 안내와 작성창 닫힘을 확인했다. 이 안내만으로 전달 성공을 판정하지 않았다.
4. 받은편지함에서 같은 합성 제목 한 건을 확인했다. 상세의 sandbox iframe 안에서 합성 본문 일치를 확인했고 첨부 파일명도 표시됐다. 첨부 다운로드 및 실제 바이트 해시는 아래 후속 검증에서 확인했다.
5. 합성 메일의 별표 설정과 읽지 않음 변경을 수행하고 새로고침 후 두 상태가 유지됨을 확인했다. 읽음으로 복원했다.
6. 보관함 이동 후 해당 편지함에서 합성 메일 한 건과 별표 보존을 확인했다.
7. 휴지통 이동 후 해당 편지함에서 한 건을 확인하고 받은편지함으로 복원했다. 영구 삭제하지 않았다.
8. 받은편지함의 합성 메일을 읽음 상태로 열고 별표를 해제했다. 합성 메일과 테스트 첨부 파일은 보존했다. 기존 메일·서버 설정·보안 설정은 변경하지 않았다.

## 발견한 이동 경계 문제와 다음 단계

후속 소스 수정: [다중 편지함 이동 수정](TASTEMAIL_MAILBOX_MOVE_20261008.md). 아래 내용은 수정 전 실계정 관찰 이력이다. 후속 수정은 개인·공유 경로 및 용량 투영의 합성 계약과 로컬 빌드로 검증했으며, 수정 후 실계정 재검증은 아직 하지 않았다.

- 이동·휴지통·복원 이후 보낸편지함에는 이 합성 제목이 표시되지 않았다. 이를 전송 실패로 취급하지 않았으며 재발송하지 않았다.
- 현재 Rust `tastemail-store`의 제출 구현은 같은 `message_id`를 로컬 수신 편지함과 발신자의 sent 편지함에 연결한다.
- 프런트엔드 `moveLiveMailOnce`는 현재 메시지의 `systemIds`에 속하는 모든 연결을 제거한 뒤 목적지 연결을 추가한다. 따라서 자기 수신 메일을 받은편지함에서 이동하면 sent 연결까지 제거된다. 공유 이동에도 같은 형태의 연결 제거 코드가 있다.
- 다음 구현 작업: 이동의 원본 편지함 범위와 보낸편지함 연결 보존 정책을 정리하고, 개인/공유 경로의 다중 편지함 메시지 회귀 검사를 추가한다. 이번 문서는 문제 발견 증거이며 수정 완료 기록이 아니다.
- 외부 발송, 접근 거부·세션 만료·실제 통제 장애, 전체 언어/화면 회귀, 모든 데이터 일치 검증은 완료하지 않았다.

앱 소스와 빌드 입력은 이번 검증에서 변경하지 않아 기존 테스트·빌드를 반복하지 않았다.

2026-10-01 작성 계약 재확인: 현재 프런트 `createDraftWithContext`는 `textBody`·`htmlBody`·`bodyValues` 및 첨부 `disposition`·`cid`를 전달한다. Rust `crates/tastemail-api/src/lib.rs`의 첨부 준비 경로는 업로드 소유권·MIME 형식 일치와 CID를 확인하고, 예약 경로는 UTC `HOLDUNTIL`과 서버 최대 지연 시간을 검증한다. 기존 합성 어댑터 검사에는 HTML/CID 초안, 예약 목록·취소 및 응답 불확실성이 포함되어 있다. 따라서 남은 항목은 API 형식을 추측해 새로 구현하는 작업이 아니라 실제 MIME 왕복·예약 큐·수신 결과 검증이다. 소스 조회만으로 배포 버전이나 실제 발송 성공을 증명하지 않는다. 이번 확인은 읽기 전용이며 기존 검사를 다시 실행하지 않았다.

2026-10-01 추가 live 다국어 화면 검증은 브라우저 제어 시간 초과로 중단됐다. 임시 탭이 `/zh-hant/rules`에 도달한 것은 탭 목록으로 확인했지만, 중간 측정 결과가 반환되지 않아 전체 경로 통과로 기록하지 않는다. 연결 복구 후 DOM 조회도 명령 전달 전에 시간 초과됐으며 임시 뷰포트 초기화·탭 닫기도 완료 확인이 되지 않았다. 사용자 개발 서버나 메일 서버는 재시작하지 않았다. 기존 성공 빌드·합성 계약·mock 화면 결과는 그대로 유지하며 추가 live 화면 검증은 미검증으로 남긴다.

2026-10-01 실계정 검증 전제 조회: 로그인된 로컬 7540의 `/ko/mailboxes`에서 `공용 편지함이 없습니다.`를, `/ko/security`의 2단계 인증 섹션에서 `인증 앱(TOTP)이 비활성화되어 있습니다.`를 확인했다. 따라서 현재 계정으로 공용 권한 조합이나 실제 MFA 챌린지를 검증할 수 없다. 이를 코드 미구현이나 서비스 장애로 해석하지 않는다. 권한 부여·MFA 활성화·계정 생성·로그아웃은 수행하지 않았으며, 해당 기능이 준비된 테스트 계정 로그인에 대한 사용자 응답을 기다린다.

2026-10-01 핵심 순수 검사 세 개의 현재 실행 결과와 입력 SHA-256을 [기계 판독용 검증 체크포인트](TASTEMAIL_VERIFICATION_CHECKPOINT.json)에 저장했다. 응답 분류·중복 방지·실패 이후 큐 처리·용량 투영 검사 모두 종료 코드 0이다. 실제 서버 장애 후 브라우저 상태 복구나 MFA 인증 성공의 증거로 확대하지 않는다. 다음 재개 시 입력 해시·런타임이 같으면 해당 검사 결과를 재사용하고 호출자 변경은 별도로 확인한다.

1. 현재 변경과 직접 관련된 실패 복구·중복 방지 합성 검사의 기존 결과를 재사용 가능한지 확인한다. 입력이 바뀐 경우에만 해당 검사부터 다시 실행한다.
2. 보호된 검증 환경에서 실제 MFA·세션 만료·권한 부족과 공용 계정 경계를 확인한다. 인증정보 변경은 사용자가 직접 처리한다.
3. 승인된 테스트 계정과 구체적인 수신자를 정한 뒤 CID/HTML·예약·실패 발송 경계를 확인한다. 실제 서비스 장애나 일반 메일 변경을 검증 수단으로 사용하지 않는다.
4. 최종 변경 범위의 mock/live·10개 언어·모바일/데스크톱 회귀 및 필수 정적/빌드 게이트를 완료한다. 이전 기록만으로 현재 산출물의 완료를 주장하지 않는다.

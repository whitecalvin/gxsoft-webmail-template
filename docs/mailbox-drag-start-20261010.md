# 편지함 이동 시작 점검

## 최신 정책

- 사용자의 후속 요청에 따라 편지함 간 이동 금지를 해제했다. 사용자 편지함과 폴더 모두 목적지가 될 수 있다. 자신/하위로 이동, 기본 편지함 목적지, 이름 충돌, 존재하지 않는 목적지는 계속 차단한다. 아래의 금지 정책 기록은 변경 전 진단이다.
- 합성 회귀 검사에서 편지함 목적지 및 그 하위 가상 폴더 목적지 허용을 검증했다. 계층 이동이며 목록 순서 변경은 아니다. 실제 브라우저에서 목적지 버튼 활성화까지만 검증하고 기존 편지함 저장은 실행하지 않는다.

- 실제 목록의 뉴스·개발·Github·ChatGPT는 모두 편지함 종류이며 최상위에 있다. 현재 계약은 폴더 안으로의 계층 이동만 지원하고, 편지함을 다른 편지함 안에 넣거나 같은 부모 내 순서를 바꾸는 기능은 제공하지 않는다. 따라서 현재 목록에는 유효한 이동 목적지가 없다.
- 이동 시작 시 루트 목적지 행이 목록 앞에 삽입되어 기존 행이 밀리는 문제를 수정했다. 목적지를 목록 뒤에 배치한다.
- 실제 브라우저의 Github 손잡이 선택 전후 Y=377.34375로 동일하고 aria-pressed=true를 확인했다. 루트 목적지는 이미 최상위이므로 비활성이다. Escape 취소 후 임시 탭을 닫았다. 기존 편지함 이동이나 서버 쓰기는 수행하지 않았다.
- 드래그 회귀 검사 통과: 계층·편지함 목적지 금지·순환·충돌·중복 요청·마우스/터치 취소. 실제 유효한 목적지에 드롭하여 저장하는 검증과 목록 순서 변경 구현은 별도 범위다.

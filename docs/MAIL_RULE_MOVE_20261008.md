# 메일 규칙 — 편지함으로 이동

- 일반 편집기에 이동 동작과 현재 계정의 대상 편지함 선택을 추가했다.
- MailProvider의 기존 편지함 목록을 재사용하며 별도 요청이나 자동 저장을 하지 않는다.
- 이동은 서버가 이미 지원하는 `require "fileinto"; fileinto "이름";` 형식으로 저장한다. 받은편지함에 명시적으로 복사하는 `keep`은 추가하지 않는다.
- 이동 선택 시 후속 규칙 중단을 기본으로 켠다. 사용자는 이를 변경할 수 있으며, 다른 규칙에 명시적 `keep`이 있으면 별도 받은편지함 저장이 발생할 수 있다.
- 적용 대상은 규칙 저장·활성화 이후 새로 수신하는 메일이다. 기존 메일 일괄 이동은 하지 않는다.
- 기존 v1 규칙의 직렬화 형식은 유지하고 이동 동작만 v2 메타데이터를 사용한다. 알 수 없는 원본은 고급 편집으로 보존한다.
- 삭제·이름 변경된 목적지는 자동 변경하거나 재생성하지 않는다. 현재 목록 확인 실패 및 대상 부재 시 GUI 규칙 저장을 차단한다. 임의 고급 Sieve의 검증은 기존 서버 책임이다.
- 대상 이름의 제어 문자를 거부하고 따옴표·역슬래시를 Sieve 문자열로 이스케이프한다.
- 서버 소스·운영 DB·계정 규칙 및 실제 메일은 이 구현 과정에서 변경하지 않았다.

## 회귀 검증

`scripts/test-simple-mail-rule.mjs`: 기존 규칙 왕복, 이동 원본 왕복, 한국어·계층 경로·이스케이프, 대상 부재, UI 동작 전환, 받은편지함 명시적 복사 없음, 저장 전 검사.

`scripts/test-mail-rules-empty-view.mjs`: 실제 JSX의 빈 상태와 기존 편집·저장 UI 보존.

실제 서버에 규칙을 저장하고 메일을 수신하여 분류하는 운영 검증은 수행하지 않는다.

### 확인 결과

- 개발 테스트 137개 통과. 저장 경합 검사의 누락된 주입 변수를 보완한 뒤 그 검사만 다시 실행했다.
- 이동 원본·UI 및 저장 경합의 production 모드 테스트 통과.
- ESLint 전체 검사, 10개 언어 키 및 사용처 검사 통과.
- 별도 `.next-folder-drag` 출력의 Webpack 운영 빌드 통과. 테스트 로더 수정은 애플리케이션 빌드 입력을 바꾸지 않아 재빌드하지 않았다.
- 실제 브라우저 시각 검증 및 서버 저장·수신 분류 검증은 미실시.

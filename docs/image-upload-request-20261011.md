# 브랜드·계정 아바타 로컬 이미지 업로드

사용자의 '서버에 요청하고 구현하자' 승인에 따라 `tastedev-mail` 세션에 서버 구현을 요청했다. 서버 소스 구현 요청이며 운영 배포, 실제 DB 마이그레이션 실행, 실제 계정 설정 변경, 서비스 재시작 승인은 포함하지 않는다.

## 서버에 요청한 계약

- 관리자 전용 브랜드 이미지와 로그인한 자기 계정의 아바타를 분리한다.
- 업로드·조회·교체·삭제, 서버 영속 저장, SSR 초기 이미지 메타데이터를 제공한다.
- 서버가 지원하는 래스터 MIME/시그니처/실제 디코딩 검사와 바이트·픽셀 제한을 확정한다. SVG·HTML 및 임의 원격 URL은 받지 않는다.
- 소유권, revision/expectedRevision, 정확한 저장 영수증, 변경 충돌·응답 불명 및 중복 요청 처리를 명시한다.
- 캐시·이미지 제공 경로, 삭제 후 기본 아이콘 처리, 계정 전환·로그아웃 격리를 정의한다.
- 정확한 API 경로·메서드·요청 본문·오류, 마이그레이션 및 회귀 검증 결과를 문서로 전달한다. API는 프런트엔드에서 추측하지 않는다.

## 프런트 공통 구현

`components/ui/ImageFilePicker.tsx`와 `lib/local-image-file.ts`를 추가했다. 로컬 파일 선택, MIME/시그니처/크기 사전 검사, 브라우저 디코딩과 픽셀 제한, 미리보기, 선택 해제, 늦은 결과 무시, bitmap/object URL 해제를 지원한다. 지원 MIME과 제한 값은 서버 계약을 확인한 호출자가 전달한다. 현 단계에서 임의 서버 제한을 정하지 않았다.

미리보기는 일시적인 blob URL만 사용하며 브라우저 저장소에 이미지 데이터를 기록하거나 자동 업로드하지 않는다. 서버 저장 성공으로 표시하지 않는다. 사용자 문구는 호출자가 전달하므로 실제 화면 연결 시 기존 10개 언어 카탈로그에 함께 추가한다.

서버 API 계약(resources/guides/dev-01/tastemail-image-assets-20261011/API.md)을 확인하고 관리자 > 브랜딩과 설정 > 계정 및 발신 주소에 실제 파일 선택·저장·제거 UI를 연결했다. 업로드는 원시 파일 바이트를 전송하며 입력 제한은 2 MiB/2048×2048이다. `/api/mail/images/{brand|avatar}` BFF가 고정 서버 API에만 접근하며 본인 아바타 인증 토큰은 URL로 노출하지 않는다. 삭제는 공통 ConfirmDialog를 사용한다.

로고와 본인 아바타 메타데이터는 루트 SSR에서 조회한다. 로고는 헤더·사이드바·관리자·로그인에, 본인 아바타는 AccountIcon에 적용한다. 공유 계정 이미지 API는 서버에서 지원하지 않으므로 기존 아이콘/이모지를 유지한다. 이미지 삭제 시 기존 아이콘/이니셜로 복귀한다. 요청 중에는 중복 변경을 차단하고, 결과 불명은 동일 요청 ID/개정/파일만 재시도한다. 영수증 확인 후 현재 메타데이터를 다시 읽는다. 계정·세션 변경 시 이미지 provider를 새로 마운트한다.

사용자가 서버 배포 완료를 알렸지만 실제 배포 버전·DB 0067 적용·인증된 운영 업로드는 이 프런트 검증에서 직접 확인하지 않았다. 브라우저 접근 제한으로 파일 대화상자와 실제 업로드 GUI 검증도 미실행이다. 실제 계정 이미지를 시험 목적으로 변경하지 않는다.

`scripts/test-local-image-picker.mjs`는 합성 파일과 합성 이미지 디코더로 입력 제한·bitmap 해제·timeout 후 늦은 디코딩·SSR·선택/해제·object URL 해제·닫힌 화면의 늦은 선택을 검사한다. 실제 브라우저 이미지 디코딩·로컬 파일 대화상자·서버 저장 검증과는 별도다.

## 오류 상태 후속 검증

### 2026-10-11 배포 후 무인증 상태 확인

호스트 읽기 전용 관찰에서 7540 Node의 상위 프로세스가 `dev-secure` 실행이고 127.0.0.1:16711 리스너 소유자는 SSH임을 확인했다. `.env.development.local`에는 현재 코드가 거부하는 원격 평문 주소가 남아 있으나 실행 스크립트는 프로세스 환경에 loopback 주소를 지정한다. 파일 값만으로 실행 장애를 단정하거나 파일/서비스를 수정하지 않았다.

확인된 SSH 터널을 통해 인증정보·쿠키 없이 `/health`는 200/service=tastedev-mail/status=ok, 공개 `/api/branding/image`는 200/revision 있음/image 없음/no-store를 반환했다. 본인 `/api/user/avatar`는 무인증 조회를 401/no-store로 거부했다. 응답 원문·이미지 ID·인증정보는 출력하지 않았다. 이 관찰은 터널 연결과 배포된 공개 이미지 메타데이터 경로·아바타 무인증 경계를 입증한다. 서버 버전, 운영 DB 전체 마이그레이션 상태, 본인 아바타 영속 저장·권한 조합, 실제 업로드 및 브라우저 렌더링 완료를 입증하지 않는다. 실제 계정·메일·설정 변경은 없었다.

2026-10-11 후속 게이트: `node scripts/test-image-asset-settings.mjs`, 변경 파일 ESLint, `GXWEBMAIL_BUILD_DIR=.next-gmail-start-validation npm run build -- --webpack` 각각 exit 0. 프로덕션 BUILD_ID는 `kB4JHPIB9E6KcGMvlhnwi`다. 소스 SHA-256: `lib/image-assets.ts` = `7C4D065E91678009A1B573A8787A3BDE3881293E62ED5E5753AB99FE529A4950`, `components/settings/ImageAssetSettings.tsx` = `B6829FC42E7332710F33022466646078576118BBC357E94EDCB900596C3972A3`, 시험 스크립트 = `9AF8580D859706E13C820AA2112CBCF664A6D0285607843C3654E0811D8ADD33`, lockfile = `5A4F03E0B2E2174C5FF39B311CD12C6B51A092F48D1F89980B61C26F4A50363C`. 이후 문서만 변경했으므로 앱 재빌드는 하지 않는다. 이 증거는 이미지 설정 변경 범위의 정적/합성 검증이며 실서버·전체 화면 회귀 완료가 아니다.

이미지 설정은 401 세션 만료, 403 권한 부족, 429 요청 제한을 기존 `liveService`의 다국어 문구로 구분한다. 401/403 이후에는 이전 메타데이터로 저장하지 못하게 하고 재조회를 요구한다. 409는 충돌 재조회, 413은 파일 크기 오류, 400 invalidImage는 디코딩 오류로 표시한다. 5xx 또는 네트워크 단절은 결과 불명으로 유지하며 동일 요청만 재시도한다. `test-image-asset-settings.mjs`는 실제 TSX 콜백의 401/403/429 분리·중복 잠금·불명 재시도·충돌 재조회·화면 종료를 합성 응답으로 검증했다. 번역 카탈로그는 바꾸지 않았으므로 직전 10개 언어 키 검사 결과를 재사용한다.

# 편지함 경로 동기화 및 선택 규칙 적용 — 서버 변경 준비

상태: 소스 조사 완료. 서버 채팅으로 요청 전송, 서버 수정, 배포, 마이그레이션 및 실제 메일 적용은 수행하지 않았다. 별도 요청 승인이 필요하다. 아래는 필요한 계약 설계이며 현재 제공되는 API로 오인하면 안 된다.

## 확인한 현재 계약

- 프런트엔드 `lib/simple-mail-rule.ts`는 이동 대상을 이름으로 저장한다. GUI 메타데이터의 `mailbox`와 Sieve `fileinto` 문자열이 같은 경로를 갖는다.
- 서버 `crates/tastemail-store/src/lib.rs`의 `perform_rename_mailbox`는 해당 계정 편지함과 하위 경로를 변경하지만 규칙 소스 갱신은 없다. 개인 편지함 API와 IMAP 이름 변경이 이 공통 함수를 호출한다.
- 서버 `crates/tastemail-api/src/retrospective_rules.rs`의 `PlanRequest`는 `mailboxId`, `expectedRevision`만 받으며 알 수 없는 필드는 거절한다.
- 서버 `crates/tastemail-store/src/retrospective_rules.rs`는 계획 생성과 실행 재검증에서 `build_snapshot`을 호출한다. 현재는 특정 규칙을 지정할 수 없다. 전체 활성 규칙을 적용하는 기존 버튼에 단일 규칙 버튼을 연결하면 사용자 요청과 다른 규칙까지 실행한다.

## 1. 편지함 이동·이름 변경 시 규칙 동기화

- 해당 계정만 대상으로 편지함 변경과 규칙 경로 변경을 한 트랜잭션에서 확정한다. 상위 편지함 이동 시 실제 변경되는 모든 하위 경로를 함께 처리한다.
- 정확한 이동 대상 경로를 매핑한다. 비슷한 접두사나 발신자·제목·주석까지 문자열 치환하지 않는다.
- GUI 규칙은 메타데이터와 실행 Sieve 소스를 함께 갱신해 시각 편집기에서 다시 읽을 수 있어야 한다. 고급/기존 Sieve는 구문에 기반해 안전하게 처리하거나 지원 불가능한 참조가 있으면 변경 전에 충돌을 반환한다. 잘못된 대상 상태로 일부만 성공시키지 않는다.
- 계정 규칙 revision을 변경해 이동 전 열린 편집기의 저장과 기존 적용 계획 실행을 충돌로 거절한다. 비활성 규칙도 대상 경로를 유지한다.
- 웹 개인 편지함 이동과 IMAP 이름 변경 모두 동일한 동기화 정책을 적용한다.
- 테스트: 단일/상위 이동, 이름 변경, 유사 접두사 제외, 인용/이스케이프 이름, GUI 재파싱, 다른 계정 불변, rollback, 동시 저장 충돌, 기존 계획 무효화.

## 2. 선택한 규칙만 기존 메일에 적용

- 서버가 저장된 규칙 ID를 지정하는 계획 생성을 지원해야 한다. 필드 및 응답은 서버 구현과 합의한 뒤 프런트엔드에 연결한다.
- 규칙 ID 소유권과 expectedRevision을 검증한다. 요청이 다른 계정의 규칙을 평가하거나 전체 규칙으로 조용히 대체되지 않아야 한다.
- 선택한 규칙의 ID 및 소스/상태를 계획에 고정하고 결과에도 적용 범위를 식별할 수 있어야 한다. 실행 시 같은 선택 범위를 재검증한다.
- 미저장 규칙은 먼저 저장하도록 안내한다. 비활성 규칙을 수동으로 한 번 적용할 수 있는지는 계약에서 명시하며, 수동 적용 때문에 수신 규칙 활성 상태를 자동으로 바꾸지 않는다.
- 기존 미리보기 → 공통 확인 창 → 실행 흐름, 계정/편지함 제한, revision/만료 검사, 결과 불확실 시 같은 계획 조회, 동일 idempotency key 재시도 정책을 유지한다.
- UI는 규칙 항목의 ‘적용하기’에서 해당 규칙 이름과 원본 편지함을 표시한다. 클릭만으로 전체 규칙 저장·메일 이동·삭제가 실행되지 않는다.
- 테스트: 다른 활성 규칙 제외, 조건 불일치 메일 불변, 다른 계정 ID 거절, 규칙 삭제/수정/편지함 변경 충돌, 미저장 버튼 제한, 취소 무변경, 중복 실행 방지, 보낸편지함 등 다른 소속 보존.

## 검증 경계

이 문서는 로컬 준비 작업이다. 기존 서버 계약을 확장하거나 운영 기능 완료를 증명하지 않는다. 승인 후 서버 계약이 확인되면 프런트엔드 BFF·계획 응답 검증·규칙 항목 버튼을 함께 연결한다. 실제 데이터 검증은 승인된 새 합성 메일 범위에서만 수행한다.

이 프로젝트는 **디자인·인터랙션 프로토타입**이며, 아직 운영 검증을 마친 메일 클라이언트가 아닙니다.

- **실제 TASTEMAIL API 연결이 필요합니다.** mock 모드·시연 로그인·시연 데이터는 제공하지 않습니다. 서버 주소는 서버 전용 `TASTEMAIL_API_URL`로 지정하고, 표시·아이콘 등 브라우저 환경설정은 서버 데이터와 구분합니다.
- **live 모드는 부분 연동 상태입니다.** TASTEMAIL 로그인/MFA·세션, 개인 메일 읽기·검색·첨부 다운로드·상태 변경·시스템 편지함 이동, 일반 텍스트·서식 HTML 작성·초안·첨부 업로드·발송 큐 제출을 연결했습니다. 주소록·캘린더·결재·메일 규칙의 일부 변경과 관리자 권한의 격리 조회·처리도 서버 계약에 연결했습니다. 공용 편지함은 읽기·첨부 다운로드, `mayWrite` 계정의 읽음·별표 변경과 같은 계정의 받은편지함·보관함·스팸·휴지통·사용자 지정 편지함 간 이동 및 휴지통 내 영구 삭제, 읽기·쓰기·발송 권한이 있는 계정의 새 메일 작성·초안 재편집·발송을 지원합니다. 임시보관함·보낸편지함을 이동 대상으로 제공하지 않습니다. 합성 JMAP 계약과 공유 테스트 계정의 초안 저장·재편집·교체, 동일 공유 주소 자기 발송·수신 및 별표 변경·복원을 확인했습니다. HTML 초안 재편집은 CID 참조와 인증된 이미지 미리보기를 연결했고 개인 테스트 계정에서 HTML·CID 자기 수신과 CID 초안 저장·재편집·재저장을 확인했습니다. 서식 있는 live 본문은 제한된 래스터 이미지를 업로드한 뒤 미리보기를 CID로 직렬화하며, 일반 텍스트 모드에서는 일반 첨부로 추가합니다. 관리자 생성과 사용자/그룹 권한 편집은 `/admin/shared-mailboxes`에 연결했습니다. 업무 편지함 화면 자체에는 권한 편집을 제공하지 않으며, 실제 권한 변경 결과는 아직 배포 검증하지 않았습니다. 예약 발송은 서버가 광고한 최대 지연 시간 안에서 UTC HOLDUNTIL로 연결했고 합성 계약 검사는 통과했지만, 개인 테스트 계정의 예약 등록·취소를 확인했습니다. 예약 시각의 실제 전달과 공용 예약 변경은 미검증입니다. 앞서 확인한 별도 테스트 계정의 자체 수신 메일 2통은 받은편지함과 보낸편지함에 나타났고, 첨부 117바이트의 SHA-256이 원본과 일치했습니다. 공유 보관함·스팸·휴지통 이동 및 복원을 확인했습니다. 120바이트 공유 첨부 업로드·자기 발송·다운로드 해시 일치도 확인했습니다. 공유 영구 삭제·대용량 첨부·권한 거부 조합, 개인 휴지통 영구 삭제, 외부 도메인 전달, 발송 실패·응답 중단은 미검증입니다. 상세 범위는 [연동 현황](docs/TASTEMAIL_INTEGRATION_GAPS.md)을 참조하세요.
- live HTML 메일은 본문 높이에 맞는 sandbox iframe에 표시해 읽기 영역의 스크롤 하나만 사용합니다. 새 사용자 기본값은 `항상 표시`이며, 이전에 저장한 `연락처만 표시`·`표시 안 함` 설정은 그대로 유지합니다. 이미지가 차단된 메일에서는 메일별로 표시하거나 `항상 표시`를 선택해 이후 메일에도 적용할 수 있습니다. HTTPS 이미지 로딩은 발신자에게 열람 사실을 알릴 수 있으며, 메일별 선택은 다른 메일로 이동하면 초기화됩니다. CID 본문 이미지는 인증된 첨부 경로로 제한된 크기만 읽습니다. 로컬 브라우저의 실제 HTML 메일 1건에서 외부 이미지와 단일 스크롤을 확인했지만 다른 메일·브라우저는 미검증입니다.
- 개인·공용 메일함과 검색 결과는 제목·발신자·미리보기 등 목록용 속성만 요청하고, 본문이 없는 응답이면 선택한 한 통의 상세 내용을 조회합니다. 공용 상세 조회는 서버에서 해당 계정의 읽기 권한을 다시 확인합니다. 이전 서버처럼 목록에서 본문까지 반환하면 즉시 표시하는 호환 경로를 사용합니다. 로컬 TASTEMAIL 소스에는 선택 속성과 본문 값 플래그를 적용하는 코드가 작업 중이지만 배포 여부는 확인되지 않았고, 실제 목록·검색 속도도 측정하지 않았습니다.
- 캘린더 live 모드에서는 참석자 이메일을 넣어 일정을 만들고 초대 일정의 취소를 요청할 수 있습니다. 서버가 초대·취소 알림을 발송할 수 있으므로 화면에 안내합니다. 초대 일정을 수정할 때 서버에서 현재 revision과 참석자 목록을 다시 읽어 목록을 보존하며, 변경 초대장 발송 가능성을 확인받습니다. 참석자 목록 자체의 편집은 제공하지 않습니다. 시스템 편지함에서 메일을 옮길 때는 사용자 지정 편지함 소속을 보존하고, 사용자 지정 편지함에서 옮길 때는 선택한 출발 편지함 소속만 제거합니다. 서버 계약이 없는 설정 화면은 live 모드에서 샘플 상태·조작 대신 미연동 안내를 표시합니다. 언어·접근성·자유형 커스터마이저는 브라우저 로컬 설정이며 live 계정 테마는 서버에 저장합니다. 단축키는 live 모드에서 미구현 안내를 표시합니다. 실제 계정의 캘린더 조회 API와 사이드바 메일함 요약, 선택한 테스트 메일의 받은편지함↔보관함 및 받은편지함↔스팸 이동·복원을 재조회로 확인했습니다. 일정 초대·취소와 다른 메일 이동 경로는 미검증입니다.
- live 공통 사이드바는 메일 화면 외의 업무 페이지에서 인증된 메일함 요약만 읽어 수치와 용량을 표시합니다. 이를 위해 메일 본문을 불러오지 않으며, 요약 조회 실패 시 mock 수치로 대체하지 않고 오류·재시도를 표시합니다. 서버가 반환한 역할 없는 개인 사용자 지정 편지함도 목록에 표시하고 선택 시 해당 편지함의 메일을 읽으며, 검색 화면의 편지함 필터에도 포함합니다. 사용자 지정 편지함의 생성·이름 변경·빈 편지함 삭제는 `POST /api/mail/folders` BFF와 TASTEMAIL `/api/personal-folders` REST 계약으로 연결합니다. JMAP에서 직접 생성하는 것으로 설명하지 않습니다. 시스템↔사용자 지정 편지함과 사용자 지정 편지함 간 이동은 연결했지만 실제 계정에서는 변경하지 않았습니다.
- live 작성 창의 받는 사람 자동완성은 인증된 서버 경유로 개인 연락처와 사용 이력의 추천을 읽습니다. live 격리 화면에는 관리자 전용 받은편지함 해제·영구 삭제를 확인 대화상자와 함께 연결했습니다. 처리 결과가 불명확하면 성공으로 표시하지 않고 목록 확인을 안내합니다. 테스트 계정에서 추천 1건의 표시와 Enter 선택을 확인했지만 터치 선택·복수 추천과 격리 변경은 아직 검증하지 않았으며, 관리자 콘솔의 격리 일괄 처리는 연결했지만 실제 변경 검증은 아직 완료하지 않았습니다.
- live `/files` 화면은 실제 메일 첨부를 검색·다운로드하며 시연용 저장 용량·대용량 링크·정리 동작을 표시하지 않습니다. live `/security`는 TOTP 상태·남은 복구 코드·세션·보안 활동을 실제 서버에서 읽고, 확인 대화상자 후 다른 기기 세션을 개별 또는 모두 해제할 수 있습니다. 현재 세션은 이 화면에서 해제하지 않으며, MFA 등 나머지 보안 설정 변경은 미연동입니다. 실제 계정에서 첨부 검색·보안 조회 API의 HTTP 200, 파일 목록·필터와 보안 화면의 TOTP·세션·활동 표시, 보낸 메일 첨부 1개의 Next.js 경유 다운로드 크기 일치를 확인했습니다. 별도 테스트 계정의 파일 화면에서 테스트 첨부를 브라우저로 내려받아 원본과 크기·SHA-256 일치를 확인했습니다. 다른 기기 세션 해제 결과는 미검증입니다.
- live `/settings/signature`는 서버가 제공하는 발신자 주소별 텍스트·HTML 서명을 읽고 저장합니다. 새 개인 메일에는 선택한 발신자의 텍스트 서명을 적용하고, HTML 서명이 설정돼 있으면 서식 편집기에 함께 삽입합니다. 기존 초안·본문과 옵션 로드 전에 사용자가 입력한 내용은 덮어쓰지 않습니다. 공용 편지함은 서버의 텍스트 서명을 유지합니다. 합성 JMAP 작성 옵션 계약은 통과했지만 실제 계정의 서명 삽입·발송 결과는 미검증입니다.
- 로그인은 TASTEMAIL 서버 인증만 사용합니다. live 업무·설정·관리자 페이지는 서버 레이아웃에서 TASTEMAIL 세션을 확인한 뒤에만 렌더링하며, 클라이언트 이동 시에도 세션을 다시 확인합니다. 로그인·가입·설치 화면은 공개 경로입니다. API 경로는 별도로 인증·권한을 확인합니다. live 인증 토큰은 HttpOnly 쿠키에만 보관하며 브라우저 저장소에 넣지 않습니다. live 로그인 폼과 세션 경로는 원격 브라우저의 평문 HTTP 로그인을 거부합니다. 원격 접속에는 Next.js 앞단의 HTTPS가 필요합니다.
- live 로그인 화면에서는 시연용 가입·설치 마법사 링크를 숨깁니다. live `/signup`에 직접 들어가도 가짜 가입 폼 대신 관리자 계정 발급 안내와 로그인 링크를 표시합니다.
- live `/setup`은 TASTEMAIL 설치 패키지의 초기 설정 환경 변수와 일회용 토큰·상태 파일이 연결된 경우 최초 설치 요청을 전달합니다. 이 연결이 없는 개발 환경에는 설치 서비스 없음 안내와 별도의 웹메일 API 연결 설정을 표시합니다. 일반 6711 API만으로는 최초 설치를 실행할 수 없으며, 실제 설치 서비스와 완료 후 로그인은 아직 검증하지 않았습니다.
- live 관리자 화면은 실제 관리자 권한 검사 후 운영 현황, 사용자·도메인·별칭·전달·그룹 관리, 공용 편지함 생성·사용자/그룹 위임 권한, 큐·감사 로그, 스팸·릴레이·DKIM, API 키·웹훅·백업 검증 기록·브랜딩·서버 테마·패키지·라이선스·사용량 보고서를 제공합니다. 공용 편지함 권한은 업무 화면이 아닌 `/admin/shared-mailboxes`에서 관리합니다. 변경 요청은 서버 권한 검사·같은 출처 확인·명시적 확인·중복 방지로 보호합니다. `/admin/onboarding`은 도메인·DKIM/DNS·계정·운영 점검의 서버 기반 설정 마법사이며 `/admin/system`은 원격 설치·업데이트 화면입니다. 관리자 시연 runtime이나 실패 시 mock 대체는 없습니다. 남은 API 연동과 실검증 경계는 [관리자 구현 범위](docs/TASTEMAIL_ADMIN_IMPLEMENTATION.md)에 기록했습니다.
- 미지원 기능은 안내로 구분하며 가짜 성공이나 시연 작업으로 대체하지 않습니다. 실제 예약 발송은 서버의 계정 capability와 검증된 접수 응답을 기준으로 제공합니다.
- **모든 인터랙션 요소는 명확한 동작과 피드백을 제공해야 합니다.** 무언가를 클릭했을 때 항상 눈에 보이는 실제 상태 변화나 피드백(토스트, 모달, 목록 갱신 등)이 있어야 하며, 아무 반응 없는 버튼은 없어야 합니다. 그런 버튼을 발견했다면 버그입니다.

개인 메일의 보낸편지함→휴지통 JMAP 패치와 서버 전용 API 주소 제한은 합성 검사로 확인했습니다. 이는 실서버에서 삭제가 성공했다는 뜻은 아닙니다. 메일 이동·영구 삭제의 응답 결과가 불명확하면 현재 화면에서 해당 메일의 후속 변경을 잠그고 메일함 확인 후 재시도하도록 안내합니다. 이 클라이언트 잠금은 서버 멱등성 보장이 아니며, 실제 결과 검증에는 별도 테스트 계정이 필요합니다.


[http://localhost:7540](http://localhost:7540)을 엽니다. 실행은 실제 서버 전용이며 `GXWEBMAIL_DATA_MODE`는 무시합니다. Next.js 서버는 기본적으로 같은 호스트의 `http://127.0.0.1:6711` API를 사용합니다. 로컬 `/ko/setup`의 **웹메일 API 연결**에서 `TASTEMAIL_API_URL`을 입력하고 연결 확인 후 `.env.development.local`에 저장할 수 있습니다. 다른 장비의 API에는 HTTPS 또는 검증된 로컬 SSH 터널을 사용해야 합니다. 사설 IP도 암호화를 보장하지 않으므로 LAN 평문 HTTP는 인증정보를 포함한 모든 API 요청을 보내기 전에 거부합니다. 이전 `http://192.168.0.109:6711` 설정은 직접 사용할 수 없으며, 실제 연결 대상과 안전한 전송 경로를 먼저 확정해야 합니다. 주소를 브라우저용 `NEXT_PUBLIC_` 변수로 설정하지 마세요. 로그인은 `/health` 확인을 기다리지 않고 같은 출처의 세션 API에 인증을 요청하며, 실패 원인을 응답으로 표시합니다. Rust API의 `/api/auth/session`은 `POST`·`DELETE`만 제공하므로, 기존 세션 확인은 인증된 `GET /.well-known/jmap`으로 수행합니다.

개발 화면에서 연결 설정을 저장할 때는 `.env.development.local`의 `GXWEBMAIL_CONNECTION_SETUP_TOKEN`도 입력해야 합니다. 설치 서비스가 없는 개발 화면에서 연결 설정을 열 수 있습니다. 토큰은 브라우저에 자동 전달되지 않으며, 개발 서버를 다른 장비에 노출한 상태에서는 설정 화면을 열지 마세요.

메일 API가 `192.168.0.109`의 loopback에서 실행 중이고 이 Windows 장비에서 SSH 로그인이 가능하다면, 서버의 SSH 호스트 키를 확인한 후 별도 터미널에서 `ssh -N -L 127.0.0.1:6711:127.0.0.1:6711 <SSH_USER>@192.168.0.109`로 로컬 터널을 열 수 있습니다. 그때 설치 화면의 API 주소는 `http://127.0.0.1:6711`입니다. 이전 터널·로그인 검증은 변경 전 7531 포트의 기록이며 위 6711 예제의 검증을 뜻하지 않습니다. 2026-10-06 배포 LAN API `192.168.0.109:6711`의 무인증 `/health` HTTP 200을 확인했습니다.

기타 스크립트:

```bash
npm run build   # 프로덕션 빌드
npm run start   # 프로덕션 빌드 서빙
npm run lint    # eslint
npm run check:locales # locale 키·문구 검사
npm run check:locale-usages # 정적 번역 참조 검사, 동적 키는 별도 확인
```

화면 문구는 `messages/{locale}.json`의 의미 기반 `next-intl` 메시지로 서버와 클라이언트에서 직접 렌더링합니다. `npm run check:locales`는 10개 언어의 키와 ICU 변수 일치 여부를 확인합니다. 계정 이름·메일 본문·파일 이름은 서버 콘텐츠이며 번역 대상 UI 문구가 아닙니다. 합성 데이터는 검증 스크립트에서만 사용합니다.

## 사용자 설정 시스템

`/{locale}/settings`는 일반, 메일, 메일 관리, 계정으로 나눈 사용자 설정 진입 화면입니다. 데스크톱에서는 왼쪽 설정 메뉴와 상세 화면을 함께 표시하고, 모바일에서는 그룹별 목록에서 상세 route로 이동합니다. 모바일 상세 화면에는 설정 목록으로 돌아가는 동작이 제공되며 가로 스크롤 탭을 사용하지 않습니다.

| 그룹 | 설정 route |
| --- | --- |
| 일반 | `/settings/locale`, `/settings/theme`, `/settings/accessibility` |
| 메일 | `/settings/signature`, `/settings/inbox-display`, `/settings/sending`, `/settings/away`, `/settings/notifications` |
| 메일 관리 | `/settings/labels`, `/settings/rules`, `/settings/blocked-senders` |
| 계정 | `/settings/account`, `/settings/security`, `/settings/integrations`, `/settings/shortcuts` |

시연 설정이나 장애 시 대체 데이터 없이 서버 계약이 확인된 메일 규칙·부재중 자동응답·발신자별 서명·계정 테마를 연결합니다. `/settings/theme`은 테마 ID/버전·밀도·밝기를 서버에 저장하거나 시스템·도메인 상속 테마로 복귀합니다. 인증된 설치 목록의 지원 조합만 저장하며 revision 충돌·불명확한 변경 응답 후에는 재조회가 필요합니다. 부재중 자동응답은 서버의 관리형 vacation 규칙으로 제목·공통 본문·활성화를 저장하고, 빈 새 계정에서 시작할 수 있습니다. 기간 예약·내부/외부별 문구·연락처만 회신은 미지원이며 사용자 정의 규칙과 기존 Sieve 스크립트는 덮어쓰지 않습니다. 계정 발신자 목록은 읽기 전용이고, 미연동 설정은 시연 컨트롤 대신 안내를 표시합니다. 구현과 실검증 범위는 [완료 조건 감사](docs/TASTEMAIL_ACCEPTANCE_AUDIT.md)에서 구분합니다.

사용자 설정 상태는 다음 세 단계로 구분합니다.

1. 소스에 포함된 타입 안전 기본값
2. 사용자가 마지막으로 저장한 snapshot
3. 현재 화면에서 편집 중인 draft

일반 설정은 계정별 서버 snapshot을 hydration 전에 전달받습니다. 조회 실패는 정상 기본값이나 localStorage 저장으로 대체하지 않으며 편집을 허용하지 않습니다. 저장은 expected revision과 확인된 receipt를 사용하고, 저장 결과가 불확실하면 자동 재전송 대신 GET으로 확인합니다. 취소는 확인된 저장 상태로 돌아가고 기본값 복원은 새 draft를 준비합니다. 기존 localStorage 값은 삭제하거나 자동 이전하지 않습니다. 저장하지 않은 설정 또는 테마 변경이 있으면 내부 링크 이동과 브라우저 종료 전에 이탈 경고가 동작합니다.

언어, 테마, 사이드바 상태는 기존 전역 동작과 연결됩니다.

- 언어 변경은 `next-intl` locale route를 사용하며 현재 pathname, query, hash를 유지합니다.
- 테마 및 화면 설정은 전역 커스터마이저와 같은 `ThemeContext`를 사용하고 게시하기 전까지 live preview로 적용됩니다.
- 사이드바 기본 접힘 상태는 `workspace_sidebar_collapsed` 쿠키를 서버에서 읽어 첫 렌더에 반영하므로 새로고침 시 펼쳐졌다가 접히는 현상이 없습니다.
- 업무 화면은 `(workspace)/layout.tsx`가 상속하는 공통 셸을 한 번 렌더링합니다. 화면 전환 시 사이드바·상단바·작성창을 다시 만들지 않고, 각 페이지의 `WorkspaceLayout`은 내용과 헤더 설정만 전달합니다. 현재 메일함을 다시 누르면 선택 상태를 불필요하게 초기화하지 않습니다.
- 접근성 설정은 글자 크기, 고대비, 모션 감소, 포커스 강화와 보조 기술 관련 값을 실제 문서 속성 및 CSS 변수에 반영합니다.

`/settings/accessibility`는 사용자 환경 설정이고 최상위 `/accessibility`는 별도 참고 화면입니다. 단축키 설정은 일반 계정 설정 계약으로 저장하며 실행 미지원 기능은 구분합니다. `/rules`와 이전 `/settings/filters`는 canonical `/settings/rules`로 이동합니다.

메일 규칙과 다른 기기 세션의 개별·일괄 해제는 서버에 연결했습니다. TOTP 상태·남은 복구 코드·보안 활동을 조회하고, 서버가 등록 가능 상태를 제공할 때 MFA 등록 흐름을 사용합니다. 화면 기능 존재와 실제 운영 인증·권한 검증 완료는 구분합니다.

## 디자인 시스템 메모

- 폼과 상호작용에는 `components/ui/`의 테마 대응 `Button`, `IconButton`, `Input`, `Textarea`, `Switch`, `Checkbox`, `RadioGroup`, `Dropdown`, `SegmentedControl`, `Avatar`, `Progress`, `Tabs`, `Panel`, `Modal`, `Popover`, `Toast`, `Badge`, `EmptyState`, `Skeleton`, `Spinner`, `Tooltip`을 재사용합니다.
- disabled가 아닌 모든 `<button>` / `[role="button"]`에는 전역적으로 `cursor: pointer`가 적용됩니다 (`app/globals.css` 참고) — 브라우저 기본값은 `<button>`에 이 커서를 적용하지 않습니다.
- 계정 테마 설정은 서버 저장·SSR을 사용하며 설치형 CSS/자산은 같은 출처 BFF를 통해 전달합니다. 자유형 커스터마이저의 색상·글꼴·모서리·레이아웃 값은 브라우저 로컬 설정이고 TASTEMAIL에 저장하지 않습니다.

## 알려진 한계

- 현재는 live-only이며 시연 로그인·메일 데이터 복원 모드는 없습니다. 메일/관리자 변경은 실제 효과가 있을 수 있습니다. [전체 요구사항 수용 점검](docs/live-integration-acceptance-20261011.md)에서 구현과 운영 검증을 구분합니다.
- 언어·접근성·자유형 커스터마이저 등 브라우저 로컬 설정은 기기 간에 동기화되지 않습니다. live 계정 테마·메일 규칙·서명·관리형 부재중 응답은 서버에 연결됐지만 다른 계정 설정 대부분은 미연동입니다. 설치형 패키지의 실제 전환·렌더링은 미검증이며 부모 버전 상속에는 추가 서버 계약이 필요합니다.
- live 모드의 실제 계정 로그인·목록·검색·보낸 메일 상세·페이지 이동과 선택한 테스트 메일의 읽음·별표·보관함/스팸 이동·복원을 확인했습니다. 별도 테스트 계정의 첨부 업로드·초안 보존·다운로드 일치를 확인했습니다. 다중 사용자·다른 상태 변경·첨부 초안 재저장·외부 도메인 전달·발송 실패·MFA·세션 만료는 아직 검증하지 않았습니다. 승인된 자기 수신 메일 2통 중 1통은 117바이트 텍스트 첨부와 함께 발송·수신되어 파일 크기와 SHA-256 일치를 확인했습니다.
- 관리자·보안 변경은 실제 서버 권한과 동작별 계약을 사용합니다. 운영 변경 검증은 승인된 대상과 범위에서 별도로 진행해야 합니다.
